## 4. 左侧任务栏（以代码为准）

### 原则（用户 2026-10-22 定）
任务文档读一次，当"计划清单"：它告诉我们有哪些任务、编号、层级、提到的文件。**做没做完，看代码，不看文档里的勾。** 文档很难实时更新，没更新不算错，只列为"文档可以更新的地方"，不标红。

### 来源
overlay 里一行 `tasks: { file: docs/任务列表.md, format: emoji-list }`，就能读项目已有的任务列表。GEO 的格式是 `- ✅ **S8.1**（2026-10-14；340 测试全绿）标题…`，解析出：编号、文档状态（✅ 🔨 ⏳）、标题、缩进层级、行里的日期、"用户定 / Claude 提议"、"N 测试全绿"的声明、反引号里提到的文件（猜的，T1）。标准格式（.workbench/tasks/*.md，front-matter + 复选框）同时支持。任务栏顶部写明"任务清单读自 docs/任务列表.md，几点几分读的"。

### 代码说的状态怎么判（src/progress.ts deriveStatus）
按顺序取第一条命中的：

1. 有子任务：子任务按代码都完成 → 完成；有的完成或在做 → 正在做。
2. 有提交信息提到它的编号：
   - 它带阶段编号，而提交信息已经标到后面的阶段 → **完成**（"提交信息已经标到后面的 S11.3"）。大步编号（如 S11）在代码正标在 S11.x 时 → 正在做。
   - 提交正标在它这一步 → 正在做。
   - 最近两天有提交或 Claude 刚改过 → 正在做；更早的提交且文档说完成 → 完成；更早的提交但文档没说完成 → 正在做（推测）。
3. 没有提交但提到的文件改了 → 正在做（推测）。
4. 什么痕迹都没有 → 照文档，并标明"只有文档说法"。

每个任务的面板都写"代码说：完成 — 为什么这么判"和"文档写的是 X"，两者不同时提示"文档没跟着更新，以代码为准"。

### GEO 实测
- **代码说**：最近的提交标到 S11.3（10-22 16:18）· 39 个带编号的任务按代码判断完成 37 个、正在做 2 个（S11 55%，S11.4 10%）。
- **文档写的**：S6 · 自己勾了 31 / 39，8 项没跟着代码更新。
- 正在做（2）：S11、S11.4，两条都注明"文档写的还是「待做」"。
- 待做（2）：两条没有编号的问题记录（"Perplexity 引用线一直看不到"、"Gemini 新型号常常不搜"），注明"代码里没痕迹，照文档"。
- 按代码判断已完成 54（含没有编号的拍板、收尾条目）。
- 值得看一眼（1）：S10 在任务列表里出现了 2 次。
- 文档可以更新的地方（9）：S6、S8、S9、S10、S12 等父任务文档还写"正在做"或"待做"，代码说都完成了；S6.4、S9.0 标完成之后还有提交提到它们。

### 进度条
流程状态用代码说的状态定区间，区间内位置由可用信号加权（验收项、子任务完成比例、文件改动）。代码说完成的直接 100%。只有状态没有别的信号时画在区间起点。每条进度条点开能看到公式、每个信号的值、来源与等级；"测试"信号明说"还没接测试结果（无数据）"。

### 点任务高亮
选中任务后，它提到的文件对应的方块加金色描边，目录级、文件级、符号级都生效。GEO 的任务行大多没有反引号路径，这种任务行里写明"没提到具体文件，不能在图上高亮"。
