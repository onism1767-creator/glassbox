## 3. 技术栈面板

右栏空选状态下新增"用到的技术（技术栈）"：左边是代码里实际 import 的第三方库（T0），右边是依赖清单里声明的版本（T0），对不对得上是 T1。GEO 实测：

- 14 个第三方库：pytest 27 处、httpx 24 处、structlog 15 处、fastapi 14 处、yaml 11 处、respx 11 处、psycopg 9 处、pydantic 6 处、playwright、trafilatura、rapidfuzz、tldextract、uvicorn 各 1–2 处，全部对上 pyproject.toml 里的声明与版本。
- 声明了但代码里没见 import 的 5 个：jinja2、python-multipart、hypothesis、mypy、ruff。前两个是 FastAPI 的运行时间接依赖，后三个是开发工具，都合理，但面板如实列出来，判断留给人。
- 30 个标准库模块折叠显示。
- 一开始 `conftest` 被标成"清单里没找到"的第三方库，修了 Python 的解析（错误库 E-027）。

清单解析支持 pyproject 的 `[project]` 依赖、可选依赖组、poetry 段，package.json 的两类依赖，requirements*.txt。发行名与 import 名的常见差异（PyYAML → yaml、Pillow → PIL 等）有一张别名表。

## 4. 左侧任务栏

### 来源
overlay 里一行 `tasks: { file: docs/任务列表.md, format: emoji-list }`，就能读项目已有的任务列表。GEO 的格式是 `- ✅ **S8.1**（2026-10-14；340 测试全绿）标题…`，解析出：编号、状态（✅ 完成、🔨 正在做、⏳ 待做）、标题、缩进层级、行里的日期、"用户定 / Claude 提议"、"N 测试全绿"的声明、反引号里提到的文件（猜的，T1）。标准格式（.workbench/tasks/*.md，front-matter + 复选框）同时支持。

### 项目到哪一步了
两句话并排：

- 任务列表说：正在 S6 · 完成 31 / 39 — 人或 AI 写的（T2 声明）
- 提交信息说：最近标到 S11.3（10-22 16:18） — 机器直接看到的（T0 观测）
- 判断：**文档落后于代码：任务列表还把 S6 标为正在做，提交信息已经到了 S11.3**

### 对不上的地方（GEO 实测 11 条）
- 文档落后于代码（上面那条）。
- 编号重复：S10 在任务列表里出现了 2 次。
- 子任务都完成了：S6 下面 5 个、S8 下面 7 个、S9 下面 7 个、S10 下面 3 个、S12 下面 1 个子任务全部标完成，父任务自己还标"正在做"或"待做"。
- 停滞：S6 标为正在做，但 48 小时内没有提到它的提交，也没有 Claude 触碰它提到的文件。
- 完成后仍在改：S6.4 在 10-13 标为完成，之后还有 1 个提交提到它；S9.0 同理。

这些都是任务列表自己和 git 对不上的地方，仪表盘只列出来，不替人改。

### 进度条
按设计稿 v1.2 的公式：流程状态定区间，区间内位置由可用信号加权。GEO 的任务列表没有验收项和认领文件，所以大多数任务显示"没有进度数据"而不是编一个数；父任务用子任务完成比例当信号，S6 因此显示 70%（正在做的区间上限）。每条进度条点开能看到公式、每个信号的值、来源与等级；"测试"信号明说"还没接测试结果（无数据）"。

### 点任务高亮
选中任务后，它提到的文件对应的方块加金色描边，目录级、文件级、符号级都生效。GEO 的任务行大多没有反引号路径，这种任务行里写明"没提到具体文件，不能在图上高亮"。
