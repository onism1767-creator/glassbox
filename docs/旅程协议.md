# 旅程协议：人或任何 AI 提出"这件事依次经过哪些代码"，机器两级检验

和 AI 工具无关。Claude Code 用 `skills/glassbox-journey/SKILL.md`（`glassbox journey skill <仓库>` 装进去），别的工具照本文做。

## 1. 什么是旅程

一个**假设**：从某个入口开始，依次经过这几个文件或函数。比如"用户在网页填品牌 → 建任务 → 引擎观测 → 诊断 → 渲染报告"。

- 提出的是人或 AI（T2 声明）。
- 静态检验由机器做（T1 推导）：相邻两步在 import / 调用图上有没有路。
- 动态检验由机器做（T3 验证）：带覆盖率跑指定的测试，真实碰到全部步骤才算"已验证"；验证时记下每步代码的哈希，之后代码变了就是"验证过时"，重跑才算。
- "已验证"这个词只有检验器能写，旅程里写了直接退回。

## 2. 一条旅程

```json
{
  "id": "diagnose-class",
  "name": "一类问题从指标到结论",
  "role": "聚合后的指标进诊断层，判成阶段结论，再组成报告里的话",
  "steps": [{ "node": "file:engine/aggregate.py", "note": "算指标" }, { "node": "sym:diagnosis/diagnose.py::diagnose_class" }],
  "verify": { "tests": ["tests/unit/test_recommender_diagnose.py", "tests/unit/test_narrative.py::test_zh"] }
}
```

校验，不通过整条退回并说原因：

1. `id` 小写字母、数字、`-`、`_`，1 到 41 个字符，同批不重复。
2. `name` ≤ 40 字，`role` ≤ 200 字，都要有；不含"已验证"。
3. `steps` 2 到 30 步，每步 `node` 是 `file:…` 或 `sym:…`（目录不收），必须存在于当前画布，相邻不重复；`note` ≤ 80 字。
4. `verify.tests` 可选，1 到 20 个，pytest 用例 id 或测试文件；测试文件必须在索引里。

存在 `状态目录/journeys.yaml`（缺省 `仓库/.workbench/journeys.yaml`）。机器写的验证记录在旁边的 `journeys-verified.json`，别手改。

## 3. 静态检验怎么算

相邻两步 A → B，在文件级的图（import 边 + 调用边归到文件）上宽度优先找路，最多 4 跳；两步都是函数时先在调用图上找：

| 结果 | 意思 |
|---|---|
| 直接 | A 直接 import 或调用 B |
| 经过 n 个文件 | A → … → B，中间文件列出来 |
| 反向 | 只有 B → A 的路：数据回流或回调，流程上仍可能是先 A 后 B |
| 由 C 串起来 | 没有 A、B 之间的路，但有个 C 同时用到两者：典型的调度器模式 |
| 断链 | 4 跳内什么都没有；可能是动态分发，也可能是旅程写错了 |

每一跳带证据（文件:行号），面板里可点开看代码。

## 4. 动态检验怎么算

```bash
glassbox journey verify <id> <仓库>
```

用项目自己的解释器 `coverage run -m pytest <指定的测试>`，结果写到 `状态目录/test-results/journeys/<id>/`（不碰全量跑的结果）。真实碰到的文件 = 覆盖率里 covered_lines > 0 的文件。

| 情况 | 状态 |
|---|---|
| 测试全过，碰到全部步骤 | 已验证（T3） |
| 已验证，但之后有步骤的代码变了 | 验证过时，重跑才算 |
| 测试失败，或只碰到部分步骤 | 验证没过，面板上标出没碰到的步 |

静态断链和动态验证同时存在时，以动态为准，断链只作提示。

## 5. 三个入口

```bash
glassbox journey list [仓库] [--json]
glassbox journey set [仓库] --file 批.json [--author 名字]
glassbox journey verify <id> [仓库]
glassbox journey entries [仓库]          # 入口候选：路由、CLI 子命令、main（正则扫的，T0）
```

HTTP（`glassbox serve` 时）：`GET /api/journeys`、`POST /api/journeys`（body `{ items, author }`）、`POST /api/journeys/verify?id=…`（同步等跑完）。
