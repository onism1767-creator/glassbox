# 标注协议：人或任何 AI 给画布写人话名字

和 AI 工具无关：能跑命令、能读写 JSON 就能用。Claude Code 用 `skills/glassbox-annotate/SKILL.md`（`glassbox annotate skill <仓库>` 装进去），别的工具照本文做。

## 1. 什么是标注

机器算得出"目录 engine 有 12 个文件，resolve.py 被 9 个测试跑过"，算不出"它叫跳转链解析，负责把引用的网址解析到最终落点"。后一句是**标注**：一个节点的人话名字（`name`）和一句话职责（`role`），加上写它时看的依据（`basis`）和节点当时的内容哈希（`hash`）。

- 真相等级 T2 声明。画布上显示成「名字（术语）」，面板里职责和依据可点开看代码。
- 结构永远不由标注决定：标注指向不存在的节点直接退回。
- 节点变了，标注自动标"过时"，画布不再用它当名字；节点没了标"没对象"。

## 2. 节点与哈希

| 节点 | id | 哈希按什么算 | 什么时候过时 |
|---|---|---|---|
| 目录 | `dir:engine`（根目录 `dir:.`） | 目录里的文件清单 | 文件增删改名 |
| 文件 | `file:engine/models.py` | 文件内容 | 内容变 |
| 函数或类 | `sym:engine/models.py::Model.save` | 它自己那几行源码 | 它的源码变（同文件别处变不算） |

## 3. 三个入口

命令行（服务开着就走 HTTP，秒回；没开本地索引一次）：

```bash
glassbox annotate todo <仓库> [--kind dir|file|symbol] [--dir 目录] [--in 文件] [--limit N] [--json]
glassbox annotate set <仓库> --file 批.json [--author 名字]
glassbox annotate show <仓库> [--stale] [--json]
```

HTTP（`glassbox serve` 时，`http://127.0.0.1:4400`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/annotations/todo?kind=&dir=&file=&limit=` | 待标和过时的节点，带哈希和上下文 |
| POST | `/api/annotations` | body `{ "items": [...], "author": "名字" }` 或直接数组；返回 `accepted`、`rejected`（带原因） |
| GET | `/api/annotations` | 现有标注与状态汇总 |

文件：`状态目录/annotations.yaml`（缺省 `仓库/.workbench/annotations.yaml`），人能读、git 能 diff。别手改 `hash`。

## 4. 一条标注

```json
{ "node": "file:engine/resolve.py", "name": "跳转链解析", "role": "跟着 HTTP 跳转把引用的网址解析到最终落点，只读响应头", "basis": [{ "path": "engine/resolve.py", "line": 57 }], "hash": "<todo 给的>" }
```

校验，不通过整条退回并说原因：

1. `node` 存在于当前画布。
2. `name` 非空 ≤ 40 字，别带括号（画布会自动加「（术语）」）；`role` 非空 ≤ 200 字；不含"已验证"。
3. `basis` ≥ 1 条，`path` 在索引里，`line` 不超过文件行数，且落在节点里（文件：同一文件；目录：目录内；函数或类：它的行号范围，必须给行号）。
4. `hash` 等于节点现在的哈希，否则"过期"，重新 `todo` 再写。
5. 同一批里同一节点不重复。

## 5. 推荐流程

1. `todo` 拿清单（先目录，再被 import 最多的文件）。
2. 读项目的 CLAUDE.md、架构书、任务列表，名字用项目已有的词。
3. 读节点源码，写 JSON；读不懂不写。
4. `set`，退回的改了再交。
5. 代码改完一阵后 `show --stale`，重写过时的。
