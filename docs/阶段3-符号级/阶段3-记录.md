日期：2026-10-21　验收标准：任选一个 GEO 函数，列出调用者与被调用者，与手工核对一致　结果：**一致，通过**

## 1. 做法：语法层加精确层

| 层 | 做什么 | 技术 | 等级 | 文件 |
|---|---|---|---|---|
| 符号 | 每个文件里的函数、类、方法，带限定名（如 Tool.run）与起止行 | tree-sitter 遍历定义节点，栈式记录外层 | T0 | src/symbols.ts |
| 调用点 | 每个调用表达式，归属到包含它的最内层定义；模块顶层代码记为 `文件::<module>` | tree-sitter 调用节点 + 行号包含关系 | T0 | src/calls.ts |
| 语法层解析 | 用本文件定义、import 表（名字、别名、模块别名、包再导出最多跳 3 次）、self/cls 同类方法、类构造函数解析被调用者 | 自写名字表 | T0 | src/calls.ts |
| 未解析分类 | 内置、外部库、需要类型信息、可能继承、名字未知、复杂表达式，各给原因 | 内置名单 + 外部 import 表 | T0 | src/calls.ts |
| 精确层 | 对"需要类型信息 / 可能继承 / 名字未知"的 Python 调用，驱动 pyright 语言服务器做「跳到定义」，定义落在仓库内某个符号范围里就升级为调用边，落在 venv / 标准库里记为外部定义 | 自写 JSON-RPC 客户端，stdio 协议，workspace/configuration 回传解释器路径 | T0 | src/pyright.ts |

每条调用边都带 `resolution`：same-file、import、self、pyright。画布和表盘据此着色，用户能看出"这条边是怎么知道的"。

## 2. 为什么不是 scip-python

设计稿 v1.1 选的是 Sourcegraph 的 SCIP 索引器。实测 scip-python 0.6.7 在 Windows 上启动即崩：它用 `path.sep` 构造正则，Windows 的分隔符是反斜杠，正则非法。这是它自己的 bug。

替代是直接驱动 pyright 语言服务器。scip-python 本来就是建在 pyright 上的，所以精度同源；pyright 是纯 JS、npm 可装、Windows 可用；代价是每个未解析调用点一次请求，而不是一次性产出索引。GEO 上 1734 次请求 14.8 秒，可接受。SCIP 的位置仍然保留：将来在 macOS / Linux 上或 scip-python 修了之后可以换回去，接口不变。

## 6. 命令

```
glassbox symbols <仓库> [--file 路径]     符号与调用边统计、未解析分类、精确层耗时
glassbox calls <名字> <仓库>             某符号的调用者、被调用者、未解析项
glassbox snapshot <仓库>                 快照现在含 symbols、call_edges、unresolved_calls 三张表
--no-precise                            只跑语法层
```

## 7. 路上遇到的

- scip-python 的 Windows 崩溃（第 2 节）。
- 语言服务器关闭时序：先 `shutdown` 再 `exit`，否则残余写入会触发无人处理的 socket 错误把整个进程带崩。
- 包的 `__init__.py` 再导出：`from other import Tool` 要沿 `other/__init__.py` 的 `from .tool import Tool` 再跳一次才能落到定义。

## 8. 留到后面的

- JS/TS 的精确层：tsserver 或 scip-typescript（后者 Windows 未测）。语法层已覆盖 JS/TS。
- 继承：`self.x()` 调到父类方法时，语法层标"可能继承"，精确层能解；类层次本身还没建。
- 增量：每次全量重算，GEO 规模 15 秒（含 pyright）；阶段 5 做实时时要按文件增量。
