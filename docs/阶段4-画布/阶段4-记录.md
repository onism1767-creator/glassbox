## 1. 做了什么

| 部分 | 内容 | 技术 | 文件 |
|---|---|---|---|
| 工程 | 独立的前端工程，构建产物由 glassbox 自己的服务静态提供 | Vite 7、React 19、TypeScript | web/ |
| 服务 | `glassbox serve`：`/api/snapshot` 给快照，`/api/file` 给源码行（限仓库内、2 MB 以内），其余静态文件；无快照时先生成 | Node http，无依赖 | src/serve.ts |
| 数据适配 | 快照建索引，按级别生成图：目录级（顶层目录 + 目录间边）、文件级（某目录的文件 + 目录内边 + 进出端口）、符号级（某文件的函数类方法 + 调用边 + 进出端口） | 纯函数 | web/src/model.ts |
| 布局 | ELK layered，方向向右；目录级按分区排泳道：上游（依赖分层包的 tests、scripts）→ L 高 → L 低 → 资源（docs、config、根目录）；文件级与符号级三分区：谁依赖我 / 我 / 我依赖谁 | elkjs 0.12，`elk.partitioning` | web/src/layout.ts |
| 画布 | 节点、边、泳道背景、小地图、缩放控件；缩放小于 0.55 时隐藏副标题与徽章 | @xyflow/react 12 | web/src/App.tsx、nodes.tsx |
| 着色 | 边：违规红、白名单黄、普通灰，粗细按数量；调用边按解析方式四色，pyright 推断用虚线；节点左侧色条表示自基线新增 / 修改 / 删除 | CSS 变量 | web/src/styles.css |
| 面板 | 选中目录：层与规则来源、文件数、依赖进出、违规、白名单及放行依据、自基线改动。选中文件：import 逐条状态、被谁 import、违规、符号列表、出边证据。选中符号：调用者、被调用者（带解析方式与证据行）、未解析调用与原因。每个数字带真相等级标记；点证据行加载源码片段并高亮那一行 | React | web/src/Panel.tsx |
| 导航 | 双击下钻，面包屑回退，端口节点"跳过去"，搜索框按文件名或函数名跳转并聚焦 | — | web/src/App.tsx |
