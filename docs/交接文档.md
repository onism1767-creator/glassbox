## 4. 规矩（用户定的，别破）

1. **画布是代码的函数**：结构只由机器推导；人和 AI 只写绑定到真实节点的标注；真相分级 T0 观测 / T1 推导 / T2 声明 / T3 验证，"已验证"只有检验器能写。
2. **所有界面文字是"人话（专业术语）"格式**，统一出处 `web/src/words.ts`；数字可点开看来源与等级。
3. **任务状态以代码为准**：任务文档只当计划清单，文档没更新是提示不是错误。
4. **不往 GEO 仓库写文件**。用户批过的例外只有两次：2026-10-27 往 GEO 架构书末尾追加了「附录:v0.4.29 代码对照回写」，只追加不动正文；2026-11-03 把 hooks 和两个 skill 装进 GEO 的 `.claude/`。这些都已经或会被管 GEO 的会话一并提交进 GEO 仓库（它的提交会把工作区里的改动全收走，所以往 GEO 写任何东西都等于交给它提交）。
5. 读被观测项目的文本一律按 `\r?\n` 切行，算哈希也先把换行统一成 LF（E-039：GEO 文件被存成 CRLF 后任务栏空了；E-040：换行一翻，几百条标注假过时）。GEO 开着 `core.autocrlf=true`，工作区里的换行随时会变。
6. 每一步：先说做法（技术、备选、为什么），做完写记录 + 截图，更新错误库、记忆、README，`git commit`（`feat(阶段N): …`，末尾 `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`）并 push。
7. 用户不是程序员，解释要用简单中文；叫"宝宝"是习惯，不用在意。

## 7. 换窗口第一件事

1. 读记忆里的三条和本文件。
2. `git -C <glassbox> status` 应该干净；`git -C <GEO> status` 里有改动的话是 GEO 会话正在做、还没提交的，别碰（架构书附录早已被它提交）。
3. 用 `.claude/launch.json` 的 `glassbox-geo` 起服务，打开 127.0.0.1:4400。顶栏「人话标注」后面若有「N 条过时」，就是 GEO 又改了代码。
4. `node src/cli.ts annotate show <GEO> … --stale`：按协议续签（第 6 节第 1 条有具体办法）。
5. GEO 的 `.claude/` 里应有 `settings.json`（三个 hook）和 `skills/` 下两个 skill；GEO 会话改了文件，画布右上「刚发生了什么（活动流）」里会立刻出现一条。
