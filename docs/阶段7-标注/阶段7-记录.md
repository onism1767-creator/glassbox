# 阶段 7 记录：AI 标注——人话名字绑定到真实节点，代码变了自动过时

日期：2026-10-27。对应提交见 git log「feat(阶段7)」。协议本身见 [标注协议](../标注协议.md)，Claude Code 用的 skill 在 `skills/glassbox-annotate/SKILL.md`。

## 1. 要解决什么

机器算得出结构，算不出"这个模块叫什么、是干什么的"。阶段 6 只有 overlay 里手写的层名和目录名（T2）。这一步让 AI（或人）给目录、文件、函数或类写人话名字和一句话职责，但要守住两条原则：

- **结构的话语权在机器**：标注只能贴到画布上真实存在的节点，指向不存在的节点直接退回。
- **标签随代码失效**：每条标注记下写它时节点的内容哈希，节点变了自动标"过时"，画布不再用它当名字，等 AI 重写。nativue 的做法是 LLM 结果整体覆盖扫描结果，我们反过来。

设计稿 v1.1 第 2、4 节定的"交互式"：写标注的是当前会话里的 AI，你看得见它读了什么、写了什么；不做后台定时调 LLM。

## 2. 做法（技术、备选、为什么）

| 环节 | 用的技术 | 备选 | 为什么 |
|---|---|---|---|
| 节点与哈希 | 目录 `dir:engine` 按"里面有哪些文件"的清单算哈希；文件 `file:…` 用索引器已有的内容哈希；函数或类 `sym:路径::限定名` 用它自己那几行源码的哈希（索引时顺手算，存进 SymbolRecord.hash） | 目录按所有文件内容算；函数按整个文件算 | 目录的职责由"有什么文件"决定，一个文件改一行不该让目录名过时；函数只在自己变了才过时，同文件别处改不影响 |
| 存哪 | `状态目录/annotations.yaml`（缺省就是仓库的 `.workbench/annotations.yaml`），人能读、git 能 diff；每条带 author 和时间 | JSON；每节点一个文件 | 和 overlay、任务文件同一套"文件是真相"；一个文件够用，按节点 id 排序让 diff 稳定 |
| 校验 | 收到一批逐条查：节点存在、名字 ≤ 40 字、职责 ≤ 200 字、依据至少一条且落在节点里（文件就是它自己，目录是目录内，函数或类是它的行号范围）、行号不超过文件行数、哈希等于现在的、同批不重复、不含"已验证"。不通过整条退回并说原因，通过的立刻写入 | 只查节点存在 | 设计稿第 4 节第 3 步原文；"已验证"只有检验器能写（设计稿 v1） |
| 入口 | 三个，和 AI 工具无关：命令行 `glassbox annotate todo / set / show`（服务开着走 HTTP 秒回，没开本地索引一次）；HTTP `GET /api/annotations/todo`、`POST /api/annotations`、`GET /api/annotations`；文件本身 | 只做 MCP | 任何能跑命令、读写 JSON 的 AI 都能用；MCP 以后包一层就是 |
| 给 AI 的上下文 | `todo` 按重要性排（先目录，再被 import 最多的文件），每项带哈希、目录里的文件清单（已标的带名字）、文件里的符号清单、它 import 了谁、被 import 多少次、所在目录已有的标注名、过时的旧标注 | 让 AI 自己翻 | 少读错东西，名字口径能对齐（同目录用同一套叫法） |
| Claude Code | `skills/glassbox-annotate/SKILL.md`：先读 CLAUDE.md / 架构书的叫法，再读源码，读不懂不写；`glassbox annotate skill <仓库>` 装进目标仓库的 `.claude/skills/` | hook 自动触发 LLM | 用户定的交互式；装进 GEO 要你批（和 hooks 一样，这次没装） |
| 画布 | 有新鲜标注的节点显示「名字（术语）」，和阶段 6 的人话（术语）格式一致；过时的不改名字，挂灰色徽章「标注过时（代码变了）：旧名」；面板里「人话名字和职责」段带职责、依据（可点开看代码）、作者、时间、和当前代码一致与否（两个哈希都给）；空选面板有总览；顶栏一句话 | 过时的也照用旧名 | 过时的名字可能已经不对，宁可退回术语 |
| 实时 | 写入后服务直接重算一轮（不依赖监听）；仓库内的 `.workbench/annotations.yaml` 和仓库外状态目录的文件都另有监听，人手改也会更新；3 秒内自己写的不重复算 | 只靠监听 | 和测试结果一样：直接通知确定，监听做备份 |

## 3. 真相等级

| 显示的内容 | 来源 | 等级 |
|---|---|---|
| 名字、职责 | 人或 AI 写的 annotations.yaml | T2 声明 |
| "和当前代码一致" / "过时" / "没对象" | 写时哈希对比现在哈希 | T0 观测（哈希是机器算的） |
| 依据的行 | 标注里给的 path:line，校验过在节点里 | T2 指向 T0 |

## 4. 实测

### GEO（服务开着，走 HTTP）

```bash
glassbox annotate todo <GEO> --limit 16 --json     # 11 个目录 + 5 个被 import 最多的文件，带哈希
glassbox annotate set <GEO> --file 批.json --author claude
```

我当 AI：读了 CLAUDE.md 的分层硬边界和五个文件的 docstring，写了 16 条（11 个目录 + engine/models.py、adapters/base.py、engine/aggregate.py、diagnosis/findings.py、engine/detectors/matching.py），另故意放了 3 条坏的。报告：

```
收下 16 条，退回 3 条；标注文件现在共 16 条
  ✗ 第 17 条 file:engine/cache.py：过期：你读的版本和现在不一样（你给的 0000，现在 76c79682bdb8；文件内容）。重新看一眼再写
  ✗ 第 18 条 sym:engine/models.py::Nope：节点不存在：sym:engine/models.py::Nope（用 glassbox annotate todo 看有哪些）
  ✗ 第 19 条 dir:crawler：同一批里重复：dir:crawler
```

画布一秒内更新：目录级 11 个方块全部变成「观测引擎（engine）」「AI 接口适配器（adapters）」这样的人话名；engine 里 models.py 显示「L2 数据模型（系统宪法）（models.py）」；面板里职责、两条依据（engine/models.py:1、:7 可点开）、「claude 写于 2 分钟前」、「和当前代码一致（哈希相同，文件内容）」。顶栏「人话标注 16 条」，总览「还有 0 个目录、133 个文件没标」。

## 6. 没做和要注意的

- GEO 还有 133 个文件没标，函数或类一个都没标：`todo` 缺省不列函数或类（GEO 有 1500 多个），`--kind symbol --in 文件` 按文件列。要不要全标是你定。
- skill 没装进 GEO（要写它的 `.claude/skills/`，和 hooks 一样等你批）。
- 名字里别带括号：画布会自动加「（术语）」，带了就成「L2 数据模型（系统宪法）（models.py）」，协议里已写明。
- 标注只有名字和职责；设计稿里的"分组建议、旅程假设"留到阶段 8 旅程。
- 没有 MCP 入口，HTTP 已经够任何工具调。
