# 错误库

记录开发中遇到的错误、问题与解决方案。每条带编号，新问题往后追加；状态只有三种：已解决、绕过、未解决。
"绕过"指没有修根因，用别的路走通了，将来可能要回头。

格式：

- **现象**：看到了什么（原话或错误信息）
- **原因**：查明的根因
- **解决**：怎么处理的，改了哪里
- **教训**：下次怎么避免（可选）

## 环境与工具链

### E-001 Node 不在机器上　已解决
- 现象：`node -v` 无输出；nativue 与 glassbox 都要 Node 24。
- 原因：机器只有 Python 3.12 与 Git。
- 解决：`winget install OpenJS.NodeJS.LTS`（24.20.0），MSI 安装弹一次 UAC。新开的 shell 里 PATH 可能还没刷新，命令前加 `export PATH="/c/Program Files/nodejs:$PATH"`。
- 位置：阶段 1。

### E-002 TypeScript 7 与 @types/node 26 刚出，版本不匹配风险　绕过
- 现象：`npm view typescript version` 给 7.0.2，`@types/node` 给 26.x，而运行时是 Node 24。
- 解决：package.json 锁 `typescript ~5.9.0`、`@types/node ^24`。
- 教训：新大版本刚出时锁上一个稳定版，等生态跟上再升。

### E-003 多文件 heredoc 一次写入失败　绕过
- 现象：一条 Bash 里连写三个 TS 文件的 heredoc，报 `unexpected EOF while looking for matching '`，三个文件都没写出来。
- 原因：未查明，疑为 Bash 工具对长命令里引号的处理。
- 解决：源码文件改用 Write / Edit 工具逐个写；heredoc 只用于短的配置和文档。
- 教训：一条命令只做一件事。

### E-004 Bash 工具里的 `cd` 会改变后续命令的工作目录　已解决
- 现象：写夹具时 `cd test/fixtures`，之后的命令都从 fixtures 目录起跑，相对路径全错。
- 解决：每条命令开头显式 `cd` 到项目根，或用绝对路径。

### E-005 `.claude/launch.json` 里的反斜杠路径被吃掉　已解决
- 现象：`preview_start` 报 `Command not found: C:rogram Files…`。
- 原因：JSON 里 `C:\\Program Files` 经过启动器再处理一次，反斜杠被当转义。
- 解决：launch.json 一律用正斜杠 `C:/Program Files/nodejs/node.exe`。

### E-006 管道接 `head` 让有副作用的命令提前中断　已解决
- 现象：`node src/cli.ts snapshot … | head -8` 时进程报 `write EPIPE`。
- 原因：`head` 读满就关闭管道，后面的 stdout 写入失败；这类命令还有写文件的副作用，中断时机不可控。
- 解决：输出先重定向到文件再 `tail`，或者不用 `head`。

## tree-sitter

### E-007 tree-sitter-wasms 的语法包与 web-tree-sitter 0.27 不兼容　已解决
- 现象：`Language.load()` 在 `getDylinkMetadata → failIf` 抛空错误，路径与字节两种输入都失败。
- 原因：tree-sitter-wasms 0.1.13 的 wasm 由旧版 emscripten 编译，动态链接元数据格式与 0.27 运行时不匹配。
- 解决：换 `@vscode/tree-sitter-wasm` 0.3.1，它把运行时和各语言 wasm 打在一起、同步维护，且无安装脚本。官方 `tree-sitter-python` 等包也带 wasm，但有原生编译的 install 脚本，别人机器上容易装失败，没选。
- 位置：src/parser.ts。

### E-008 UMD 包的命名导出在 ESM 里拿不到　已解决
- 现象：`import { Parser } from "@vscode/tree-sitter-wasm"` 后 `Parser` 为 undefined，`Cannot read properties of undefined (reading 'init')`。
- 原因：该包是 UMD，`module.exports = factory()` 不能被 Node 的 CJS 词法分析识别出命名导出。
- 解决：`createRequire(import.meta.url)` 后 `require()` 取整个命名空间。类型仍从它的 d.ts 导入。
- 位置：src/parser.ts。

### E-009 `namedChildren` 元素可能为 null　已解决
- 现象：tsc 报十几处 `'node' is possibly 'null'`。
- 原因：web-tree-sitter 0.25 起 `children`、`namedChildren`、`descendantsOfType` 的元素类型是 `Node | null`。
- 解决：统一过一个 `nodes()` 过滤函数再遍历。
- 位置：src/imports.ts、src/symbols.ts、src/calls.ts、src/rules.ts。

## 索引与规则

### E-010 中文路径在终端里显示成乱码　已解决（不是 bug）
- 现象：索引输出里 `docs/报告留档` 显示为 `docs/��������`。
- 原因：Bash 工具的输出解码问题。把码点打出来是 `0x4ea7 0x54c1…`，即"产品文档"，数据本身正确；git 的 `ls-files -z` 输出 UTF-8，Node 解码也正确。
- 教训：看到乱码先验码点，别急着改代码。

### E-011 阶段序列同一秒内多个提交排序不稳定　已解决
- 现象：测试里 S1、S2 两个提交同一秒创建，时间线顺序颠倒。
- 原因：只按 ISO 时间字符串排序，相同时间的顺序取决于 Map 插入顺序，而 git log 是新在前。
- 解决：遍历前把提交倒成旧在前，再做稳定排序。
- 位置：src/history.ts `stageTimeline`。

### E-012 快照里"层级"字段的真相等级写成了一句话　已解决
- 现象：tsc 报 `"T0/T2 见 rules.provenance"` 不能赋给 `Tier`。
- 解决：从 `rules.provenance` 里找 `layers` 条目的等级填进去，守卫测试来源是 T0，手写是 T2。
- 位置：src/snapshot.ts。

### E-013 测试期望值凭记忆写错　已解决
- 现象：三处断言失败——调用点数写 13 实为 12；列号写 2 实为 6（忘了四格缩进）；未解析列表顺序假定按行。
- 解决：按夹具逐行数过再写；顺序不保证时先排序再比。
- 教训：期望值从夹具文件读，不从脑子里读。

### E-014 全局替换把函数自己替换成了递归调用　已解决
- 现象：`indexOptions()` 定义体里出现 `...(option("overlay") ? indexOptions() : {})`，无限递归。
- 原因：用脚本把 `{ overlayFile: option("overlay") }` 全部替换成 `indexOptions()`，定义体本身也命中。
- 解决：手工改回。
- 教训：全局替换前先看每一处命中。

## 符号级

### E-015 scip-python 0.6.7 在 Windows 启动即崩　绕过
- 现象：`SyntaxError: Invalid regular expression: /\/g: \ at end of pattern`，出在它的 `PythonEnvironment.ts:4 new RegExp(path.sep, 'g')`。
- 原因：Windows 的 `path.sep` 是反斜杠，直接拼进正则就是非法模式。这是上游 bug。
- 解决：精确层改为驱动 pyright 语言服务器（scip-python 本就建在 pyright 上），自写 JSON-RPC 客户端做「跳到定义」。SCIP 的接口位置保留。
- 位置：src/pyright.ts；设计稿 v1.1 第 5 节的技术表需要更新这一行。
- 待办：关注上游是否修复；macOS / Linux 上可以直接用 scip-python。

### E-016 语言服务器关闭时序导致整个进程崩溃　已解决
- 现象：`glassbox snapshot` 在 pyright 跑完后报 `Error: write EPIPE … Socket._writeGeneric`，快照没写出来；`symbols` 命令却偶尔正常。
- 原因：关闭时直接 `kill`，残余写入落到已关闭的子进程 stdin，socket 的 error 事件无人处理，Node 把它当未捕获异常。
- 解决：按协议先请求 `shutdown`，再通知 `exit`，两秒没退出再强杀；stdin / stdout / 进程都挂 error 处理；写入前检查 `destroyed` 与 `writable`。
- 位置：src/pyright.ts `LspClient.close`、`send`。

### E-017 包的 `__init__.py` 再导出解析不到　已解决
- 现象：`from other import Tool`，而 `Tool` 定义在 `other/tool.py`，由 `other/__init__.py` 再导出；语法层找不到定义。
- 解决：在目标文件找不到模块级定义时，沿它的 import 表再跳，最多 3 次。
- 位置：src/calls.ts `Resolver.moduleLevel`。

## 画布

### E-018 没有连线的目录被 ELK 堆到左上角，不进它们的泳道　已解决
- 现象：根目录、.claude、config、docs 四个孤立节点排在画布左上，与分区设置无关。
- 原因：ELK 默认把每个连通分量分开布局再打包（`elk.separateConnectedComponents` 默认 true），分区约束只在分量内生效，孤立节点各自成一个分量。
- 解决：根图加 `"elk.separateConnectedComponents": "false"`。
- 位置：web/src/layout.ts。

### E-019 初次适配视图没把整张图收进来　已解决
- 现象：右侧两条泳道被截在画布外，`fitView` 调了却像没调。
- 原因：在 `setNodes` 之后用 `requestAnimationFrame` 立刻调 `fitView`，此时 React Flow 还没量到节点尺寸；节点只给了 `style.width/height`，没给 `width/height` 字段。
- 解决：节点同时给 `width`、`height` 字段；`<ReactFlow>` 用 `key={layoutId}` 按每次布局重挂载并开 `fitView` 属性，由 React Flow 在节点就绪后自己适配；下钻后聚焦选中节点用 `useNodesInitialized` 触发。
- 位置：web/src/App.tsx、web/src/layout.ts。

### E-020 npm 12 默认拦下依赖的安装脚本　绕过
- 现象：`npm warn install-scripts esbuild@0.28.2 (postinstall: node install.js)`。
- 原因：npm 12 起第三方包的 install 脚本需要显式批准。
- 解决：esbuild 不跑 postinstall 也能用（平台二进制走 optionalDependencies），Vite 构建正常。若将来构建报找不到 esbuild 二进制，运行 `npm install-scripts approve esbuild` 后重装。

## 参照项目 nativue-ai（不是我们的 bug，但影响使用）

### N-001 自动测试 19 项中 2 项在 Windows 失败
- 原因：测试夹具创建符号链接，Windows 普通用户无此权限（EPERM）。产品本身不受影响。

### N-002 服务只认 `127.0.0.1`
- 现象：用 `localhost:4317` 打开返回 `{"error":"Invalid host"}`。
- 原因：防 DNS 重绑定的 Host 校验。
- 解决：用 `http://127.0.0.1:4317`。

### N-003 分析导入因仓库变动被拒绝
- 现象：`Stale analysis: rescan and analyze the current inputId`。
- 原因：分析期间另一会话提交了代码，输入版本过期。设计如此。
- 解决：重扫、按文本锚点重新生成草稿、再导入。这也是 glassbox 要做基线差异的直接理由。
