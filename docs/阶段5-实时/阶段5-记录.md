# 阶段 5 记录：实时

日期：2026-10-22　验收：改一个文件两秒内画布变化；故意加一条违规 import 两秒内变红　结果：**通过，643 毫秒**

## 1. 做了什么

| 部分 | 内容 | 技术 | 文件 |
|---|---|---|---|
| 增量索引 | 每个文件的解析结果（import 语句、符号、调用点）按内容哈希缓存；每轮只重读 mtime 或大小变了的文件，哈希没变就复用；删掉的文件从缓存移除。跨文件的解析（import 解析、边、规则检验、调用边）是纯计算，每轮全量重跑 | Indexer 类 | src/indexer.ts |
| 解析拆分 | import、调用点的提取与解析分成两步：提取按文件缓存，解析每轮重算 | tree-sitter | src/imports.ts、src/calls.ts、src/symbols.ts |
| pyright 常驻 | 语言服务器会话跨轮存活，文件变了发 didChange；只重问被改的文件；导入方的精确层延后到紧随其后的"细化"轮，先快后准。精确层的结果按文件缓存，目标符号消失的边自动过滤 | 自写 JSON-RPC，shutdown → exit 的关闭时序 | src/pyright.ts |
| 监听与重算 | `fs.watch` 递归监听，250 毫秒去抖合并连续改动；`.git/HEAD`、`refs/`、`logs/HEAD` 变化刷新历史与基线；重算期间来的变化排队到下一轮 | Node 内置 | src/runtime.ts |
| 推送 | SSE：`/api/stream` 推 `update`（变了哪些文件、耗时、违规数）与 `activity`（事件）；画布收到后重新拉快照、原地更新节点，不重置视角、不丢选中 | EventSource | src/runtime.ts、web/src/App.tsx |
| hooks | `bin/glassbox-hook.js` 读 Claude Code hook 的 stdin JSON，POST 到 `/api/hook`，1.5 秒超时、永远静默退出 0；`glassbox hooks install <仓库>` 把 SessionStart、PostToolUse（Edit、Write、MultiEdit、NotebookEdit、Bash）、Stop 三组 hook 合并进仓库的 `.claude/settings.json`，保留原有配置 | Node http | bin/glassbox-hook.js、src/hooks.ts |
| hook 语义 | SessionStart（startup 或 clear）记基线为当前 HEAD；PostToolUse 的编辑工具记"触碰"并立刻触发重算；Bash 记命令；cwd 或文件不在仓库内的一律拒绝 | 纯函数 | src/activity.ts |
| 活动流 | 事件追加到 状态目录/events.jsonl，内存保留最近 500 条；最近 30 分钟被 hook 触碰的文件进快照的 `activity.touched`。画布底部活动流条，顶栏"● 实时 · 更新于 x 秒前（耗时）"，被触碰的文件带"刚改 · 几秒前 · 会话"徽章，目录带"刚改 n" | — | src/activity.ts、web/src |

## 3. 两秒预算怎么花

| 环节 | 夹具实测 | GEO 预估 |
|---|---|---|
| 监听到事件 + 去抖 | 约 250 毫秒 | 同 |
| 读取与解析变化的文件 | 几十毫秒 | 几十毫秒 |
| 全局纯计算（import 解析、边、规则、调用边） | 约 100 毫秒 | 几百毫秒（1370 符号、7300 调用点） |
| pyright 重问被改文件 | 未开 | 几百毫秒 |
| 导入方的精确层 | 未开 | 延后到下一轮，不占这两秒 |
| 写 snapshot.json + 推送 | 几十毫秒 | 约 100 毫秒（600 KB） |
| sqlite 重写 | 推送之后异步 | 同 |

## 4. 路上遇到的

- 构造函数参数属性（`constructor(readonly root)`）不是可擦除语法，Node 直接跑 TS 不认，所有测试一起挂（错误库 E-021）。
- `git status` 会刷新 `.git/index`，监听把它当成提交触发第二轮重算（错误库 E-022）。
- 导入方精确层的代价：改 engine/models.py 会牵动几十个导入方，一轮做完会超两秒，所以拆成先快后准两轮。

## 5. 怎么用

```bash
npm run web:build
node src/cli.ts serve <仓库>                   # 首次全量，然后监听
node src/cli.ts hooks install <仓库>           # 把 hooks 装进仓库的 .claude/settings.json
```

装了 hooks 之后，在那个仓库里新开的 Claude Code 会话会：开始时把基线记成当时的 HEAD；每次编辑文件、跑命令都出现在活动流里；被改的文件在画布上标"刚改"。没装 hooks 也能用：文件监听和 git 不依赖任何 AI，只是看不到"谁改的"和自动基线。

## 6. 留到后面的

- 大仓库的全局纯计算还是全量；几千文件时要做按依赖子图的局部重算。
- SSE 只推"变了"，画布重拉整份快照（GEO 600 KB）；大仓库要改成增量补丁。
- 活动流只有 hook 和监听事件；阶段 6 会把任务状态变化也放进来。
