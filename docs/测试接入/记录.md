# 测试接入记录：junit 与 coverage 进画布

日期：2026-10-27。对应提交见 git log「feat(测试)」。

## 1. 要解决什么

阶段 6 的任务栏能从代码判断"做没做完"，但进度公式里的"测试"信号一直是空的，任务列表里写的「291 测试全绿」也没人核对。这一步把 pytest 的结果接进来：

- 每个文件、每个目录知道"有多少相关测试、通没通过、测试跑到了几成代码"；
- 任务知道"和它提到的文件相关的测试"的红绿，和它声明的「N 测试全绿」对照实测；
- 进度公式的测试信号有值。

## 2. 做法（技术、备选、为什么）

| 环节 | 用的技术 | 备选 | 为什么 |
|---|---|---|---|
| 通没通过 | pytest 自带的 `--junitxml`，我们用正则读 `<testcase>`，`classname` 逐段对回真实文件（`tests.unit.test_a.TestGroup` → `tests/unit/test_a.py` + 类名） | 读 pytest 的 JSON 报告插件；用 XML 库 | junit 是 pytest 自带、所有 CI 都认的格式，结构扁平，70 KB 正则够用，不加依赖 |
| 跑到了几成 | `coverage run -m pytest` + `coverage json`，用 `dynamic_context = test_function` 记"每个测试跑过哪些行" | pytest-cov 的 `--cov-context=test` | 只需要项目环境里有 coverage 一个包（GEO 没装 pytest-cov）。两种上下文写法解析器都认 |
| 测试挂到源文件 | 三级：覆盖率上下文说"这个测试跑过这个文件"（T0）；它本身就是测试文件（T0）；没上下文时按"测试文件 import 了谁"推断（T1） | 只按目录名猜（tests/unit/test_x ↔ x.py） | 上下文是机器看到的事实；import 推断是退路，等级降一级并写在面板上 |
| 结果放哪 | `glassbox test <仓库>` 用项目自己的解释器跑，结果写进 glassbox 的状态目录 `test-results/`，`COVERAGE_FILE`、`COVERAGE_RCFILE` 都指到状态目录 | 写进仓库的 `.workbench/` | 被观测的仓库另一个会话在持续提交，不往里写任何文件 |
| 实时 | 状态目录的 `test-results/*.xml|json` 单独监听，变了就重算并进活动流「测试结果更新」 | 轮询 | 和阶段 5 的文件监听同一套 |
| 大文件 | `coverage json --show-contexts` 在 GEO 上是 79 MB，跑完立刻压成只含每文件摘要和"跑过它的测试"集合的小文件（181 KB），原始文件删掉 | 直接读大文件 | 每次 mtime 变化都要整个 parse，几百 MB 内存，快照也不该带 |
| 进度 | 测试信号权重 0.3：相关测试全过 1、有红 0、没有相关测试不计；「N 测试全绿」声明和实测比：失败 0 且实测总数 ≥ 声明数才算对上 | 只看全项目红绿 | 和任务提到的文件挂钩，红才会落到具体任务上 |

## 3. 数据流和真相等级

```
pytest --junitxml → junit.xml ──┐
coverage run/json → coverage.json ─┤→ readTestResults（按 mtime 缓存）
                                   │   parseJunit：用例 id = 文件::类::函数[参数]
                                   │   parseCoverage：每文件 覆盖率 + 跑过它的测试
                                   │   contextResolver：上下文名 → junit 用例 id
                                   │   linkTests：fileStatus[文件] = {相关测试, 通过/失败/跳过, 等级, 覆盖率}
                                   ↓
快照 tests → 顶栏「测试 403 通过、40 跳过」、文件方块「测试跑到 98% · 9 个测试通过」、
            目录方块「平均覆盖率 93%」、文件面板「测试与覆盖率」、任务行「相关测试 90 个…」「验收声明核对一致」
```

| 数字 | 来源 | 等级 |
|---|---|---|
| 通过 / 失败 / 跳过 | junit.xml 的 `<testcase>` | T0 观测 |
| 覆盖率、跑到了几行 | coverage.json 的 summary | T0 观测 |
| 某文件的相关测试 | 覆盖率上下文；或它本身是测试文件 | T0 观测 |
| 某文件的相关测试（没上下文时） | 测试文件 import 图 | T1 推导 |
| 任务的测试信号 | 任务提到的文件的 fileStatus 并集 | 跟着上面走 |
| 「N 测试全绿」 | 任务列表里的话 | T2 声明，和实测对照后才给结论 |
