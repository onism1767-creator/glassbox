# 给画布写人话标注

画布的结构（有哪些目录、文件、函数，谁 import 谁）只由机器从代码推导。你只负责人话：这个东西叫什么、是干什么的。
每条标注绑定到一个真实节点，并记下写它时节点的内容哈希；代码变了标注自动标"过时"，画布不再用它当名字，等你重写。

## 步骤

1. 看还有谁没标（服务开着就是秒回；没开会本地索引一次）：

   ```bash
   glassbox annotate todo <仓库> --limit 20
   ```

   或 `--json` 拿结构化结果。每一项带：节点 id、`hash`（原样抄回）、目录里的文件清单或文件里的符号清单、它 import 了谁、被 import 多少次、所在目录已有的标注名、过时的旧标注。

2. 先读项目自己的说法：CLAUDE.md、架构书、任务列表里对这个模块的叫法和职责描述。名字尽量用项目已有的词。

3. 再读源码：文件看开头的 docstring 和符号清单，目录看里面文件的名字和已有标注，函数或类看它的行号范围。读不懂就不写那条，不要猜。

4. 写成 JSON 数组存到临时文件：

   ```json
   [
     {
       "node": "file:engine/resolve.py",
       "name": "跳转链解析",
       "role": "跟着 HTTP 跳转把引用的网址解析到最终落点，只读响应头，结果记到数据库",
       "basis": [{ "path": "engine/resolve.py", "line": 57 }, { "path": "engine/resolve.py", "line": 87 }],
       "hash": "<todo 给的 hash>"
     }
   ]
   ```

   规则：`name` ≤ 40 字、别带括号（画布会自动加「（术语）」）；`role` ≤ 200 字，说清为谁做什么；`basis` 至少一条，必须落在这个节点里（文件就是它自己，目录是它里面的文件，函数或类是它的行号范围）；`hash` 原样抄；不要写"已验证"，那个词只有检验器能写。

5. 交上去，看报告：

   ```bash
   glassbox annotate set <仓库> --file 批.json --author claude
   ```

   退回的按原因改了再交。"过期"表示代码刚变了，重新跑 `todo` 拿新哈希再写。收下的立刻进画布：方块上显示「名字（术语）」，面板里有职责和依据。

6. 用户要"刷新过时的标注"时：`glassbox annotate show <仓库> --stale` 看哪些过时，对照旧标注和现在的代码重写，同样走第 4、5 步。

## 节点 id 长什么样

- 目录：`dir:engine`，根目录是 `dir:.`
- 文件：`file:engine/models.py`
- 函数或类：`sym:engine/models.py::Model.save`（文件路径 `::` 限定名）
