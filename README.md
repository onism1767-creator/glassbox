# glassbox

**画布是代码的函数。** The canvas is a function of the code.

给用 AI 编程的人的实时仪表盘：代码结构、进度、待办全部由机器从代码、git、测试和 agent 事件推导出来。LLM 只负责贴标签，标签随代码变化自动失效。

## 为什么做

用 Claude Code 这类工具开发时，有三个看不见：看不见代码结构，看不见进度真相，看不见清晰的待办。三者根因相同：所有"看见"都经过 agent 的消化和汇报，没有任何机制校验汇报与代码是否一致。画布由 agent 维护，本质上是一张 PPT。

## 原则

- **结构只由机器推导。** 节点和边来自文件系统、import 解析、符号索引、git、测试结果、hook 事件。LLM 和人只能贴标签、提假设。
- **真相分级，由来源决定，不能自报。** T0 观测、T1 推导、T2 声明、T3 机器验证。"已验证"这个词只有检验器能写。
- **实时有精确定义。** 事实更新秒级；LLM 标注移出主路径，节流，过期灰显。
- **进度等于流程层加证据层。** 状态机说谁该做什么，证据层算 agent 触碰、提交引用、测试结果、验收 SHA，两层不一致标红。
- **架构规则进图。** 分层方向和禁用词写成规则，每条依赖边机械判定，违规标红。

## 状态

架构落地率完成：架构书里的目录树、接口伪代码、反引号里的文件、目录、类、函数名机械抽出来（T2），对照索引（T0），每项标存在或缺失，缺失的带书里的行号和相近名字提示，代码里有书里没提的另列一表；GEO 实测 87.4%，缺的 22 项都对得上真实原因。阶段 8：旅程。人或 AI 提出"这件事从入口依次经过哪些代码"的假设，机器两级检验：静态看相邻两步在 import 和调用图上连不连得上（直接、经过几个文件、由谁串起来、反向、断链），动态带覆盖率跑指定的测试，真实碰到全部步骤才算已验证（T3），代码变了自动"验证过时"；画布按步高亮、上一步下一步。设计稿 v1.1 的八步至此全部做完。阶段 7：AI 标注。人或 AI 给目录、文件、函数或类写人话名字和一句话职责，每条绑定到画布上真实存在的节点并记下内容哈希，节点变了自动过时；写入逐条校验（节点存在、依据在节点里、哈希是现在的），命令行、HTTP、文件三个入口，和 AI 工具无关，Claude Code 有现成 skill。索引器读文件、解析 import、从项目自己的守卫测试读分层规则并检验违规、提取函数与类与方法、解析调用边（语法层 + pyright 精确层）、读 git 历史与阶段标签、算会话基线差异、读依赖清单对照实际 import；画布用 React Flow 加 ELK 画成目录、文件、符号三级，泳道按层，所有文字都是"人话（专业术语）"，违规边红、白名单边标注、基线差异着色，点方块或点线看证据与真相等级；左侧任务栏读项目已有的任务列表当计划清单，做没做完以代码为准，点任务在图上高亮它的文件；测试结果（junit 与 coverage）进文件、目录和任务，"N 测试全绿"的声明和实测对照；改了一个 .py 文件，几秒后只跑和它相关的测试（覆盖率上下文知道哪些测试跑过它），结果合并进画布；服务监听仓库，改一个文件不到一秒画布就变，Claude Code 的 hooks 把会话开始、编辑、命令送进活动流并自动记基线。旅程、AI 自动标注还没有。

```bash
npm install
npm run web:build
node src/cli.ts init <仓库>                      # 写 .workbench/overlay.yaml 模板
node src/cli.ts serve <仓库>                     # 打开 http://127.0.0.1:4400，监听中；改了 .py 自动只跑相关测试（--no-auto-test 关）
node src/cli.ts hooks install <仓库>             # 把 Claude Code hooks 装进仓库的 .claude/settings.json
node src/cli.ts test <仓库>                      # 用项目自己的解释器跑 pytest（有 coverage 就带覆盖率），结果进画布
node src/cli.ts annotate todo <仓库>             # 还没标或已过时的节点，带哈希和上下文，给 AI 写人话标注用
node src/cli.ts annotate set <仓库> --file 批.json   # 交一批标注，逐条校验，收下的立刻进画布
node src/cli.ts annotate skill <仓库>            # 把"写标注"的 skill 装进仓库的 .claude/skills/
node src/cli.ts journey set <仓库> --file 批.json    # 交一批旅程假设（入口 + 有序步骤 + 验证用的测试）
node src/cli.ts journey verify <id> <仓库>       # 带覆盖率跑指定的测试，碰到全部步骤才算已验证（T3）
node src/cli.ts journey entries <仓库>           # 入口候选：路由、CLI 子命令、main
node src/cli.ts arch <仓库>                      # 架构落地率：架构书声明的文件、目录、类、函数对照代码
node src/cli.ts check <仓库>
node src/cli.ts calls <函数或类名> <仓库>
node src/cli.ts snapshot <仓库>
```

技术决定：TypeScript on Node 24；tree-sitter 做语法结构；符号级调用图用 tree-sitter 语法层加 pyright 语言服务器精确层（原定的 scip-python 在 Windows 启动即崩，见阶段 3 记录）；node:sqlite 做事实库；React Flow 加 ELK 做画布；任务是仓库内 Markdown 文件；Claude Code hooks 做实时事件，协议本身与 AI 工具无关。
